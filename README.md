# Repurpose AI

Paste a blog post / video transcript / newsletter draft → get a Twitter/X thread, LinkedIn post, Instagram caption, YouTube description, and newsletter blurb, generated by Claude.

Freemium model: 3 free generations per visitor, then NT$470/month unlimited via Lemon Squeezy subscription.

## 1. Run it locally

```bash
npm install
cp .env.example .env
```

Edit `.env` and add your `ANTHROPIC_API_KEY` (from https://console.anthropic.com/settings/keys — pay-as-you-go, a few cents per generation). Lemon Squeezy env vars are optional for local testing — without them, "Upgrade" just shows an error instead of opening checkout.

```bash
npm start
```

Open http://localhost:3000.

## 2. Set up payments (Lemon Squeezy)

Already done for this deployment — store `repurpose-ai-legochen-2026`, product "Repurpose AI Pro" at NT$470/month, checkout + webhook both wired up. The one remaining step, which only the store owner can complete, is **store activation**: Lemon Squeezy dashboard → fill in business/bank details so it can actually pay out — until that's done, checkouts run in test mode and no real money changes hands.

To set this up from scratch on a new store:
1. Create a free account at https://app.lemonsqueezy.com
2. Store → Products → New Product → set it to **Subscription** pricing → Share → copy the **Checkout link** into `LEMONSQUEEZY_CHECKOUT_URL`
3. Settings → Webhooks → Add webhook → URL: `https://yourdomain.com/api/lemon-webhook`, events: `subscription_created` and `subscription_cancelled`, and set a **Signing secret** (max 40 characters) into `LEMONSQUEEZY_WEBHOOK_SECRET`
4. Settings → General → finish business/bank info to leave test mode

## 3. Deploy

Cheapest realistic path:
- **Hosting**: Render.com or Railway.app free/low-cost tier (Node app), or Fly.io. Vercel doesn't suit this well because the app needs a persistent filesystem for `data.json` — if you want Vercel, swap the storage for a hosted Postgres (e.g. Supabase free tier) later. Note even Render/Railway's free tier has no *persistent* disk, so `data.json` resets on every redeploy — fine pre-launch, but worth fixing (see Known limitations) before real traffic.
- **Domain**: ~$10-15/year from Namecheap or Cloudflare.
- Set the same environment variables (`ANTHROPIC_API_KEY`, `LEMONSQUEEZY_*`, `ADMIN_KEY`) in your host's dashboard.

## 4. The realistic path to $2000/month

At NT$470/month (~US$15), you need **~134 paying subscribers**. Some math to keep you honest: most tools like this convert free→paid at roughly 2-5%, so you'd need on the order of 3,000-6,000 people to actually try the free tool — not just visit the landing page.

Where those users plausibly come from, roughly in order of effort-to-payoff for a solo person:
1. **Build in public on X/Twitter and LinkedIn** — post your own repurposed content (using the tool on your own posts) daily. This is the single highest-leverage channel because the tool's output IS the marketing content.
2. **r/socialmedia, r/marketing, r/SaaS, r/Entrepreneur** — share it as a free tool when you have a working link, not before (no self-promo until you've contributed genuinely).
3. **Product Hunt launch** once the MVP is polished — a decent launch can bring a few hundred visitors in a day.
4. **SEO on long-tail keywords** — "repurpose blog post to twitter thread", "video transcript to linkedin post" etc. Low competition, low volume, but compounds over months.
5. **Directly DM/email 20-30 content creators or small marketing agencies** offering free Pro access in exchange for feedback — a few will convert to paid and refer others.

Realistic timeline: most solo indie tools take **3-6 months** of consistent posting/iteration to reach a few hundred dollars MRR, and 6-12 months to approach $2000 MRR, if the tool actually solves the problem well and you stay consistent with distribution. The code is the easy 20%; distribution is the hard 80%.

## Known limitations to fix before real launch

- Free-tier tracking uses `localStorage`, so it resets if someone clears cookies or uses incognito — fine for MVP, but for a real launch add at least IP-based rate limiting as a backstop.
- No real user accounts (login) — Pro status is tied to a browser-generated anonymous ID stored in localStorage. This is fine to launch with, but if a paying user switches browsers/devices they'll appear unpaid. Adding email-based auth (e.g. magic links) is the natural next step once you have your first paying customers.
